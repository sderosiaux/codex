Ce qui fait tourner la boucle

Dans ce fork de codex, la boucle agentique tient dans trois boucles imbriquées autour d'un appel au modèle. Tout ce qui suit est lu dans le code du harness (chemins relatifs à codex-rs/), pas dans une description générale des agents.

Ce qui démarre un tour

  1. Ton prompt. Le CLI envoie Op::TurnInput en mode StartIfIdle.
  2. Un message trigger_turn d'un autre agent : spawn_agent et followup_task réveillent ainsi un sous-agent.
  3. Ce même message, arrivé trop tard pour le tour en cours : le harness démarre un nouveau tour tout seul à la fin du tour, ou après un Ctrl-C.

Il faut un thread libre, sans message trigger_turn en attente : ce message passe avant ton prompt. Op::Compact lance une compaction, pas la boucle.

Ce qui relance la boucle

  • le modèle a appelé au moins un outil ;
  • le serveur a répondu end_turn: false ;
  • le flux a été coupé pour livrer du courrier d'agent ;
  • de l'input attend, courrier compris tant que la réponse finale n'est pas affichée ;
  • un hook Stop bloque l'arrêt avec une consigne.

Aucun plafond d'itérations. Le modèle ne dit jamais « j'ai fini » : il arrête d'appeler des outils.

Ce qui l'arrête

  • une réponse sans appel d'outil que rien ne relance ;
  • un hook qui bloque l'input ou demande l'arrêt ;
  • une erreur non réessayable : fenêtre dépassée, limite d'usage, erreur fatale d'outil ;
  • Ctrl-C, la seule fin qui donne TurnAborted.

Tout le reste finit par TurnComplete, avec l'erreur attachée s'il y en a une.

Trois boucles l'une dans l'autre

C'est ce qui rend la cinématique moins linéaire qu'on ne l'imagine : chaque niveau a sa propre condition de sortie.

La tâche du tour

RegularTask::run (core/src/tasks/regular.rs) appelle run_turn, puis le rappelle avec un input vide tant que la file contient de l'input arrivé après la décision d'arrêt. Elle sort sur une erreur terminale ou une file vide.

La boucle d'échantillonnage

run_turn (core/src/session/turn.rs) vide l'input en attente, appelle le modèle, récupère les sorties d'outils, puis reboucle tant que needs_follow_up est vrai ou qu'un hook Stop bloque. C'est elle, la boucle agentique.

La requête au modèle

run_sampling_request réessaie le même prompt sur erreur réessayable : 5 fois avec backoff, puis bascule WebSocket → HTTPS pour 5 essais de plus. Quand la connexion est impossible, il réessaie sans limite, avec 5 à 60 s d'attente. À l'intérieur, try_run_sampling_request lit le flux et lance les outils au fil de l'eau.
